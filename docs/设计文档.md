# fuyao-skills-hub 设计文档

本地优先的技能管理工具：技能只存一份在中心库（hub，一个 git 仓库），按项目或全局把需要的技能以目录链接铺进各 AI 工具（agent，如 Claude Code、Codex）的技能目录，让同一份技能被多个 agent 共用。界面给人用，命令行给 AI 用。

## 1. core

业务规则与数据操作所在的 Rust 库；cli 只做参数解析与输出塑形，gui 只经桥搬参数与错误。

### 1.1 数据

```
hub\                          # 缺省 ~\.fuyao-skills-hub，整体是一个 git 仓库
├─ store\<键>\SKILL.md        # 技能工作副本（可改），键是库内唯一路径，如 mattpocock/skills/tdd
├─ archive\<键>\SKILL.md      # 归档面：归档技能整目录搬到这里，结构与 store 一致
├─ agents\<名>.toml           # agent 配置覆盖
├─ projects.toml              # 登记簿：谁在哪个项目或全局用了哪个技能
├─ hub.toml                   # 库配置（结构版本）
└─ logs\                      # 日志，按天滚动，留 30 天
```

- 工作副本是编辑面：改动 tracked 面的写命令落盘后自动提交，git 是审计日志。提交消息就是该命令计划里的提交步，`--dry-run` 列出的提交步与实跑产生的提交逐字一致（含顺序）。
- 定位链按 `GLOSSARY.md` 的顺序解析；空环境变量视为未设置；家目录解析失败硬报错并提示 `FSH_HUB` / `--hub`。
- 登记簿分两段：项目段以规范化绝对路径为表键（Windows 下带 `\\?\` 前缀），技能记录挂在 `[[projects."<路径>".skills]]`，字段 `key`、`agents`、`link`。
- 全局段只有 `[[globals.skills]]` 一层，字段相同，没有项目身份。

### 1.2 入库与归档

- `fsh add <目录>`：名字唯一来源是 `SKILL.md` 的 `name`，必须等于目录名；源发现与批量入库见 1.6。
- `fsh archive` 把工作副本整目录移入 `archive\`；`fsh remove` 连 store 与 archive 的副本一起删；两者遇到仍被引用的技能不整批失败，该技能进 `skipped` 报告，其余照做。
- `fsh restore` 把归档副本整目录移回 `store\`；store 同名键占用（含普通文件占位）进 `skipped`（`conflict`），不做静默改名。

### 1.3 使用与撤回

- 一次可服务一个全局目标 + 零到多个项目目标，全目标一起预检，任一不合格整次不动盘。
- 落点（技能目录里的实际位置）= 技能目录 + 键末段；多个 agent 落到同一处只建一个入口，登记仍保留全部 agent。
- 链接三级降级：符号链接 → junction（Windows 目录联接）→ 拷贝；实际用哪种记在登记簿的 `link`，一条记录只能是一种。一个目标的第一个落点按降级链定档，同目标其余落点按这一定下的档位建立——办不到即整笔回滚，不静默降级；`use` 与 `move` 的重链共用这一条。
- 拷贝不跟源同步，改完不回流；云盘路径会破坏链接，体检会报。
- 同一目标已登记、或落点已被占：该技能进 `skipped`（`already_registered` / `destination_occupied`），不覆盖已有记录与文件，其余技能照做；先 `unuse` 再重铺。`fsh use` 只对未归档技能执行。
- `fsh unuse`：`-a`/`--agent` 必填，只撤点名的 agent，共用落点留到最后一个 agent 撤走；名单点满整条记录即整条撤回。copy 被手改要 `-f`/`--force`，形态不符仍拒绝。

### 1.4 体检与配置

- `fsh doctor`：十项检查——hub 可写、非云盘、链接能力、装配完整、内置技能铺到全局、内置技能内容与程序一致、登记簿死记录、孤儿落点、孤儿目录、键末段与 frontmatter name 一致；只报不动，三态 ok/warn/fail，有 FAIL 时退出码 1。
- agent 是数据：内置名单随程序发布，`agents\<名>.toml` 同名整项覆盖、新文件名新增。
- 配置字段 `display_name`、`skills_dir`（相对项目根）、`global_skills_dir`；后两者至少给一个。
- `global_skills_dir` 写 `~`、环境变量或绝对路径，配置回显原文，落点时展开成绝对路径；非法写报 `invalid_agent_config`。
- 内置表的全局位适配环境变量（名单与语义对齐 skills.sh）：专有变量（claude-code=`CLAUDE_CONFIG_DIR`、grok=`GROK_HOME`、hermes-agent=`HERMES_HOME`、mistral-vibe=`VIBE_HOME`、autohand-code=`AUTOHAND_HOME`、reasonix=`REASONIX_HOME`，Windows 未设置回落 `%APPDATA%\reasonix`）、XDG 根（amp、universal、replit、opencode、goose、devin，未设置回落 `~/.config`；universal 回落保持 `~/.agents/skills`）、openclaw 按存在性在 `~/.openclaw`→`~/.clawdbot`→`~/.moltbot` 里选。变量已设置且非空时以变量值为根拼子路径，未设置或空值静默回落表里默认字面量；用户 TOML 覆盖项不带适配、显式写未设置变量仍报错。
- 错误对外是稳定 snake_case 码，常见如 `invalid_skill_key`、`skill_not_found`、`already_registered`、`not_registered`、`archived`、`modified_copy`、`lock_held`。
- 日志写 `logs\` 与 stderr，非阻塞，默认 `info`，`RUST_LOG` 可覆盖。

### 1.5 内容检索

- `fsh-core::search`：hub 内纯文本内容检索，入口 `search(hub_root, query, &SearchOptions)`。
- 遍历只认 hub 根 `.gitignore` 的白名单规则：store、archive、agents、hub.toml 可见，logs、.lock 与根级散件天然不可见；归档技能在归档面内，同样可被检索。遍历根恒为 hub 根——范围与 glob 都是命中过滤层（前缀过滤、正向并集保留负向剔除），任何调用形状都穿不透白名单。
- 命中含键投影（store 内取「最近含 SKILL.md 的祖先目录」，store 外省略）、正斜杠相对路径、行文本与 spans（行内字符偏移，按 Unicode 标量值计）；恒定排序：路径升序、行号升序。
- 匹配语义：缺省 smart-case（模式全小写才忽略大小写），可强制忽略大小写、字面量与整词；rg 的 `-m` 不占，limit 属于自家（缺省 200，截断只裁 hits，total 始终精确并标 truncated）。
- 上下文行：`SearchOptions.context` 收 `ContextWindow`（命中行前后各 n 行；`-C` 同时给前后、`-A`/`-B` 各给一侧，零跨度等同不展开），检索在 limit 截断之后按留下的命中展开成上下文行组——文件按路径升序、组内行号升序、重叠区间合并、同一行只出一次、读盘失败按缺席降级、命中行文本取命中本身。行组只服务文本形态，不进 `--json` 信封。
- 错误码：`search_path_invalid`（范围路径含 `..`/绝对/反斜杠/盘符或不存在）、`search_pattern_invalid`（模式或 glob 编译失败）。

### 1.6 选择器与批量写路径

- 选择器是所有吃技能键的动词的唯一入口：`--prefix <前缀>` 指向一套（可多段，如 `k1/k2`；省略即根，空串与全空白视同未给），`--skill <名>…` 点名这套里的技能（恒为一段、可重复，重复的名字静默去重），`--all` 表示这套里的全部技能（按段边界含更深层：`k1/k2` 命中 `k1/k2/tdd` 与 `k1/k2/db/sql`，不命中 `k1/k2b`）。点名的技能在该前缀下不存在报 `no_match`，消息附该前缀下的可用清单；技能名里写 `/` 报 `invalid_skill_key`，提示分层写进 `--prefix`。
- `--all` 与 `--skill` 互斥。`--all` 必须带前缀这条只管作用于库内已有技能的动词（archive、restore、remove、use、unuse）；`add` 例外——它的范围由源目录划定，`fsh add <目录> --all` 合法，等价于把源目录里的技能入到根下（带前缀则入到该前缀）。
- 入库的源发现是有序判定，不是枚举：源目录自身含 `SKILL.md` 即单技能并立即短路，不再看子目录；否则只检查直接子目录，含 `SKILL.md` 者为技能、不含者跳过；更深层一律不进入。扫描跳过 `.` 开头的目录与 `node_modules`，不提供开关。发现到多个而既没 `--skill` 也没 `--all` 即拒绝（`ambiguous_source`，附发现的技能名）；只发现一个时 `--all` 等价于省略。
- 批量写路径沿用既有写入口：先解析选择器（形状问题与 `no_match` 在碰盘面前拒绝），入库再把整批坏项（坏 frontmatter、名字与目录名不一致）一次收齐后统一报出；全部通过才动盘，动盘失败整批回滚。预期内的「不适用」不堵整批，该技能进 `skipped` 报告，其余照做。
- `skipped[].code` 是情形码不是动词码——码说的是为什么跳过，不按动词命名（`referenced` 在 archive 与 remove 下是同一个码）。本批实际出现的：`already_exists`（库内已有同键）、`conflict`（恢复的目标面被占，含普通文件占位）、`referenced`（仍被登记簿引用）、`already_registered`（该目标已有此技能的登记记录）、`destination_occupied`（铺装的落点已被占，含普通文件）、`not_registered` / `agent_not_registered`（撤回时没有对应的技能记录 / agent 记录）。
- 写命令以结果载荷定退出码：`applied` 为空而 `skipped` 非空 → 1（这次其实什么都没做，预演同此）；其余正常收尾 0。`no_match` 与 `ambiguous_source` 属于整批不入的错误，不进 `skipped`。
- 一次批量只产生一条自动提交。提交对象按实际动到的键定：只动一个键就点那个键（`remove(store): dead`），两个及以上写「前缀 N 个技能」（`archive(store): k1/k2 3 个技能`；前缀取这些键的共同父路径，一段都不共同时写「根」）；`move` 的对象是「旧键 -> 新键」。目标面按实际动到的面点名：往常是单一 `store`，`remove` 同时删两面时写 `store,archive`。
- `fsh list --prefix` 把浏览面收窄到该套（含更深层），与位置过滤词取交集；缺省整面。

## 2. cli

`fsh` 命令行，AI 的主要入口；只解析参数、调 core、塑形输出，不含业务规则。

`<选择器>` = `[--prefix <前缀>] (--skill <名>… | --all)`：省略前缀即根；`--all` 须带前缀（`add` 例外，范围由源目录划定）。

```bash
fsh init    [-n]                                 # 建库；已建则补缺件并把内置技能对齐进 store\builtin\
fsh add     <目录> [--prefix <前缀>] [--skill <名>… | --all] [-n]
                                                 # 入库；源自身是技能即单技能，否则只看直接子目录
fsh list    [过滤词] [--prefix <前缀>] [--archived]
                                                 # 浏览：键、description、使用清单（目标 + 链接方式 + agent）；别名 ls
fsh archive <选择器> [-n]                        # 归档
fsh remove  <选择器> [-n]                        # 彻底删除；别名 rm
fsh restore <选择器> [-n]                        # 从归档面移回 store
fsh move    --prefix <旧前缀> --skill <名> --to <新前缀> [-n]
                                                 # 重组前缀，末段不变；别名 mv
fsh use     <选择器> -a <a>[,<b>] (-g | -p <目录>…) [-n]
fsh unuse   <选择器> -a <a>[,<b>] (-g | -p <目录>…) [-f] [-n]
fsh search  <模式> [<路径>] [-i] [-F] [-w] [-g <glob>]… [-l] [-c] [-A|-B|-C <N>] [--limit <N>]
                                               # 检索 hub 内文件内容
fsh doctor
```

- 高频选项配短名，短名与长名等价、可混用：`-a`/`--agent`、`-p`/`--project`、`-g`/`--global`、`-f`/`--force`、`-n`/`--dry-run`。
- 子命令别名是显式且稳定的公开接口，`--help` 一查即得：`list`/`ls`、`remove`/`rm`、`move`/`mv`，只有这三个，其余命令没有别名。
- `-g` 分属两个域，各自成立：`search` 的 `-g` 是 glob（收窄检索的文件面，可重复），`use`/`unuse` 的 `-g` 是 global（全局技能目录）。
- `--json` 只有长选项，不配 `-j`；不做任意前缀缩写，`fsh in` 这类写法一律报 `usage`。
- 技能入口统一为 `--prefix` + `--skill`/`--all` 两段（见 1.6），不再有位置参数写整键；技能名恒为一段，要分层请写进 `--prefix`，前缀可多段、省略即根；反斜杠、空段、`.`/`..` 都报 `invalid_skill_key`。
- `fsh move` 的预演载荷同时有 `from` 与 `to`（新旧整键）；实跑另报改写的登记记录数与重链落点。
- `use` 与 `unuse` 至少给一个目标，否则 `no_target`；两者的 `-a`/`--agent` 必填。
- `-p .`/`--project .` 要显式写。
- 写操作都给 `-n`/`--dry-run`：只列动作与跳过项，不动盘。列出的动作与提交步即实跑会执行的那一份计划，逐字一致。
- `--json` 输出一行信封：`{"ok":true,"data":…}` / `{"ok":false,"error":{"code","message"}}`；不带时给人读输出：预演列动作清单、写命令一句结果陈述（完成数、跳过项与原因）、list 分块、search 平铺、doctor 逐项结论。机器格式只由 `--json` 触发。
- 退出码 0 成功、1 失败；写命令 `applied` 为空而 `skipped` 非空也是 1（这次其实什么都没做，预演同样）；`fsh doctor` 有 FAIL 也是 1；参数解析错误：带 `--json` 出 `usage` 信封，不带时 clap 的错误说明走 stderr。
- 写操作共用 hub 根 `.lock` 全局锁，抢不到报 `lock_held`，不排队；`-n`/`--dry-run` 与查询不取锁。
- 仓库 `skills\fuyao-skills-hub\` 是讲 `fsh` 用法的技能，编译期内嵌进程序，由 `fsh init` 入库到 `store\builtin\fuyao-skills-hub\`（键 `builtin/fuyao-skills-hub`）后再铺给 agent。`init` 以程序内嵌内容为准：`store\builtin\` 下非内嵌的目录会被清掉。
- `fsh search`：调 core 检索引擎（1.5 节），不含自己的匹配逻辑。flag 面只收 rg 参考的 `-i`/`-F`/`-w`/`-g`（可重复，`!` 开头剔除）/`-l`/`-c`/`-A`/`-B`/`-C` 与自有 `--limit`（缺省 200），名单外不收（rg 的 `-m` 刻意不占）。文本模式输出 `path:line:text`、正斜杠、无 ANSI 色、恒定排序；`-l` 列命中文件、`-c` 出每文件计数；上下文行 line 后带 `-` 标记、不连续组之间 `--` 分隔、文件边界裁掉越界行，仅文本模式（与 `--json` 同给报 usage）。`--json` 出 `{"hits":[{key?,path,line,text,spans}],"total":N,"truncated":bool}`。无命中退出 0；坏正则 `search_pattern_invalid`、越界路径 `search_path_invalid`、hub 未初始化 `hub_not_initialized` 各走失败信封退出 1。`-l` 与 `-c`、`-A`/`-B`/`-C` 彼此互斥。
