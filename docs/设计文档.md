# fuyao-skills-hub 设计文档

本地优先的技能管理工具：技能只存一份在中心库（hub，一个 git 仓库），按项目或全局把需要的技能以目录链接铺进各 AI 工具（agent，如 Claude Code、Codex）的技能目录，让同一份技能被多个 agent 共用。界面给人用，命令行给 AI 用。

## 0. 上手三步

1. `fsh init` 建库：缺省 `~\.fuyao-skills-hub`，也可用 `--hub` 或环境变量 `FSH_HUB` 指定；重复执行只补缺件。
2. `fsh add <目录>` 入库：把一个含 `SKILL.md` 的目录复制进库，并打首版 tag（git 版本标记）。
3. `fsh use <技能> --agent <agent>[,<agent>] --global`（或 `--project <目录>`）铺出去；撤回用 `fsh unuse`，换版本用 `fsh upgrade`。

桌面端有对应入口：未初始化时的引导页、空库时的「从目录入库…」、详情页的「使用…」。

## 1. core

业务规则与数据操作所在的 Rust 库；cli 只做参数解析与输出塑形，gui 只经桥搬参数与错误。

### 1.1 数据

```
hub\                          # 缺省 ~\.fuyao-skills-hub，整体是一个 git 仓库
├─ store\<键>\SKILL.md        # 技能工作副本（可改），键是库内唯一路径，如 mattpocock/skills/tdd
├─ export\<键>\<版本>\        # 固定版本的导出目录，按需生成、可删可重建
├─ agents\<名>.toml           # agent 配置覆盖
├─ projects.toml              # 登记簿：谁在哪个项目或全局用了哪个技能
├─ hub.toml                   # 提交身份、回收宽限 gc.grace_days
└─ logs\                      # 日志，按天滚动，留 30 天
```

- 版本的真身是 git tag `<键>/v<版本>`；工作副本是编辑面，发版才落 tag。
- 定位链：`--hub` > `FSH_HUB` > 家目录缺省；空环境变量视为未设置。
- 登记簿分两段：项目段以规范化绝对路径为表键（Windows 下带 `\\?\` 前缀），技能记录挂在 `[[projects."<路径>".skills]]`，字段 `key`、`version`（省略 = 跟最新）、`agents`、`link`。
- 全局段只有 `[[globals.skills]]` 一层，字段相同，没有项目身份。

### 1.2 版本

- `fsh add <目录>`：名字唯一来源是 `SKILL.md` 的 `name`，必须等于目录名；没写 `metadata.version` 时补 `0.1.0` 并写回文件。
- `fsh release <技能>`：号写在 `metadata.version`（带引号的 `x.y.z`），必须大于最新版本；工作副本的全部改动一起提交再打 tag。
- 界面发版把输入的号写回文件；只有与最新版本同号时才允许覆盖重发。
- `fsh archive` 删工作副本与导出目录，tag 与历史保留；`fsh remove` 连全部 tag 一起删；两者被使用中即拒绝。
- `fsh restore` 从最新 tag 取回工作副本，不打新 tag；回旧版本走 `fsh upgrade`。

### 1.3 使用与版本切换

- 一次可服务一个全局目标 + 零到多个项目目标，全目标一起预检，任一不合格整次不动盘。
- 落点（技能目录里的实际位置）= 技能目录 + 键末段；多个 agent 落到同一处只建一个入口，登记仍保留全部 agent。
- 链接三级降级：符号链接 → junction（Windows 目录联接）→ 拷贝；实际用哪种记在登记簿的 `link`，一条记录只能是一种，混用整批回滚。
- 拷贝不跟源同步，改完不回流；云盘路径会破坏链接，体检会报。
- 同一目标已登记就拒绝，换版本只能 `fsh upgrade`；`fsh use` 只对未归档技能执行。
- `fsh unuse`：给 `--agent` 只撤这些 agent，共用落点留到最后一个 agent 撤走；不给就整条撤回。copy 被手改要 `--force`，形态不符仍拒绝。
- `fsh upgrade`：旧入口改名占位、原路径建新入口、全部成功才删占位；任一失败整批还原，登记簿不动；已在目标版本零动作。
- `fsh upgrade --all`：只升「固定版本且落后」的记录，全量预检后逐条执行，失败即停并报告已完成与未开始。

### 1.4 回收、体检、配置

- `fsh gc`：清无引用的导出目录、孤儿目录与失效的项目记录（宽限内保留）；内容与 tag 不符的目录跳过；tag 和历史永不清。使用后或换靶成功后顺手清一次。
- `fsh doctor`：七项检查——hub 可写、非云盘、链接能力、装配完整、导出目录在位、项目记录有效、可回收空间；只诊断不改数据，三态 ok/warn/fail。
- agent 是数据：内置名单随程序发布，`agents\<名>.toml` 同名整项覆盖、新文件名新增。
- 配置字段 `display_name`、`skills_dir`（相对项目根）、`global_skills_dir`；后两者至少给一个。
- `global_skills_dir` 写 `~`、环境变量或绝对路径，配置回显原文，落点时展开成绝对路径；非法写报 `invalid_agent_config`。
- 错误对外是稳定 snake_case 码，常见如 `invalid_skill_key`、`skill_not_found`、`already_registered`、`not_registered`、`version_not_found`、`archived`、`modified_copy`、`lock_held`。
- 日志写 `logs\` 与 stderr，非阻塞，默认 `info`，`RUST_LOG` 可覆盖。

### 1.5 内容检索

- `fsh-core::search`：hub 内纯文本内容检索，入口 `search(hub_root, query, &SearchOptions)`。
- 遍历只认 hub 根 `.gitignore` 的白名单规则：store、agents、hub.toml 可见，export、logs、.lock 与根级散件天然不可见；归档技能无工作副本即遍历不到。遍历根恒为 hub 根——范围与 glob 都是命中过滤层（前缀过滤、正向并集保留负向剔除），任何调用形状都穿不透白名单。
- 命中含键投影（store 内取「最近含 SKILL.md 的祖先目录」，store 外省略）、正斜杠相对路径、行文本与 spans（行内字符偏移，按 Unicode 标量值计）；恒定排序：路径升序、行号升序。
- 匹配语义：缺省 smart-case（模式全小写才忽略大小写），可强制忽略大小写、字面量与整词；rg 的 `-m` 不占，limit 属于自家（缺省 200，截断只裁 hits，total 始终精确并标 truncated）。
- 错误码：`search_path_invalid`（范围路径含 `..`/绝对/反斜杠/盘符或不存在）、`search_pattern_invalid`（模式或 glob 编译失败）。

## 2. cli

`fsh` 命令行，AI 的主要入口；只解析参数、调 core、塑形输出，不含业务规则。

```bash
fsh init    [--dry-run]                          # 建库；已建则补缺件
fsh add     <目录> [--prefix <前缀>] [--dry-run]  # 入库
fsh list    [--tag <tag>]                        # 技能清单（含归档态）
fsh show    <技能>                                # 详情：SKILL.md 头部字段、版本时间线、使用记录
fsh release <技能> [--dry-run]                    # 发版
fsh archive <技能> [--dry-run]                    # 归档
fsh remove  <技能> [--dry-run]                    # 彻底删除
fsh restore <技能> [--dry-run]                    # 从最新版本恢复
fsh use     <技能>[@<版本>] --agent <a>[,<b>] (--global | --project <目录>…) [--dry-run]
fsh unuse   <技能> [--agent <a>[,<b>]] (--global | --project <目录>…) [--force] [--dry-run]
fsh upgrade <技能>[@<版本>] (--global | --project <目录>…) [--force] [--dry-run]
fsh upgrade --all [--global | --project <目录>…] [--force] [--dry-run]
fsh agents                                   # 认得的 agent：名字、目录、来源
fsh projects                                 # 已登记项目与落点状态
fsh diff    <技能> <v1> <v2>                 # 两版逐文件差异（unified diff）
fsh search  <模式> [<路径>] [-i] [-F] [-w] [-g <glob>]… [-l] [-c] [-A|-B|-C <N>] [--limit <N>]
                                               # 检索 hub 内文件内容
fsh gc      [--dry-run]
fsh doctor
```

- `<技能>` 是唯一键（`store\` 内相对路径），必须写全，不按末段模糊匹配；反斜杠、空段、`.`/`..`、版本形状的段都报 `invalid_skill_key`。
- `@<版本>` 只认三段数字；`use`、`unuse` 与单条 `upgrade` 至少给一个目标，否则 `no_target`；`upgrade --all` 不给范围就是全 hub。
- `--project .` 要显式写。
- `fsh upgrade` 的 `<技能>` 与 `--all` 必须二选一。
- 写操作都给 `--dry-run`：只列动作，不动盘。
- `--json` 输出一行信封：`{"ok":true,"data":…}` / `{"ok":false,"error":{"code","message"}}`；文本模式动作清单逐行、diff 打 patch、其余 pretty JSON。
- 退出码 0 成功、1 失败；`fsh doctor` 有 FAIL、`fsh upgrade --all` 中途失败也是 1；参数解析错误统一信封码 `usage`。
- 写操作共用 hub 根 `.lock` 全局锁，抢不到报 `lock_held`，不排队；`--dry-run` 与查询不取锁。
- 仓库 `skills\manage-skills\` 是讲 `fsh` 用法的技能，按普通技能 `fsh add` 入库后再铺给 agent。
- `fsh search`：调 core 检索引擎（1.5 节），不含自己的匹配逻辑。flag 面只收 rg 参考的 `-i`/`-F`/`-w`/`-g`（可重复，`!` 开头剔除）/`-l`/`-c`/`-A`/`-B`/`-C` 与自有 `--limit`（缺省 200），名单外不收（rg 的 `-m` 刻意不占）。文本模式输出 `path:line:text`、正斜杠、无 ANSI 色、恒定排序；`-l` 列命中文件、`-c` 出每文件计数；上下文行 line 后带 `-` 标记、不连续组之间 `--` 分隔、文件边界裁掉越界行，仅文本模式（与 `--json` 同给报 usage）。`--json` 出 `{"hits":[{key?,path,line,text,spans}],"total":N,"truncated":bool}`。无命中退出 0；坏正则 `search_pattern_invalid`、越界路径 `search_path_invalid`、hub 未初始化 `hub_not_initialized` 各走失败信封退出 1。`-l` 与 `-c`、`-A`/`-B`/`-C` 彼此互斥。

## 3. gui

Tauri 2 桌面端，React 前端；桥只搬参数与错误，业务规则全在 core。

- 桥 19 个命令，覆盖环境、初始化、库读写、项目/agent 查询、使用/升级/撤回、体检/回收、内容检索与打开数据目录。
- 文件操作走阻塞线程池；错误统一为 `{code, message}`（core 稳定码 + 中文消息）。
- 启动先读环境（hub 根、是否初始化、程序版本、平台）；未初始化显示引导页，可就地初始化或打开数据目录。
- 窗口 1280×800（最小 960×600），记住尺寸、位置、最大化与可见状态；目录选择走系统弹窗，打开数据目录用文件管理器。
- 四页：库、项目、Agent、健康。
- 库页：左侧清单（全文内容检索、全部/活跃/已归档、标签筛选、按最近更新或名称排序），右侧详情三页签。
  - 查询框走内容检索桥命令（`search_hub`，字面量匹配、上下文 1 行）：命中按 key 聚合成键集合过滤清单（任一文件命中即保留该键）；正文中含词的技能由此可被搜到。检索在途或失败时不过滤，失败给行内提示；检索词为空即不过滤。
  - 命中行在清单行下方内联渲染：`路径:行号` 定位、上下文行与基于 spans（字符偏移）的高亮命中段；每键最多展示 3 条，多余以「另有 N 处命中」收口。
  - 概览：描述、标签、最新版本、版本数、项目与全局在用数、项目落点数、`SKILL.md` 原文。
  - 版本：时间线标「当前」与「N 处在用」；可对比上一版，可勾选使用记录切到该版（无使用时禁用）。
  - 使用：全局/项目分组表（目标、Agent、版本）；两段记录都可就地解除该一条。
  - 头部动作：使用…、解除…、发版、归档/恢复、移除（仍被引用时禁用）；「解除…」按使用记录勾选多条，一次撤掉全局与多个项目。
- 项目页：项目表（技能数、落点异常数、最近使用）与单项目明细（版本、agent、链接方式、落点是否存在），可就地解除。
- Agent 页：认得的 agent 表（名称与键、来源、项目技能位、全局技能位）。
- 健康页：七项体检按 fail/warn/ok 分组；回收先预演再执行，执行前确认。
- 外壳：侧栏折叠、明暗主题、`Ctrl+K` 命令面板（跳页面/技能/agent、打开数据目录、刷新当前页）。
- 页面里的写操作串行执行，成功后刷新全部数据；锁被占时提示「另一个 fsh 进程正在写，稍后重试」。
- 桥的撤回命令收目标集合（`unuse_skill` 传全局开关 + 项目路径列表 + 一份 agent 名单），一次调用撤完全部目标，任一目标不合格整次不动盘；界面里全局与项目用法都能撤回。
