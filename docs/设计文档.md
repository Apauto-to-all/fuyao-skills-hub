# fuyao-skills-hub 设计文档

> 本文档是个人版功能全集：要实现什么、已经有什么、还缺什么。
> 状态标注：✅ 已实现（fsh-core，测试全绿）· 🟡 部分实现 · ⬜ 未实现

---

## 0. 一页摘要

一个本地优先的 skills 管理工具：一个中心库（hub）存所有 skill，按项目把需要的 skill 以链接方式铺进项目目录，同时铺给各种 AI 工具（Claude Code / Codex / Cursor / DSH 等）。可视化界面（给人）+ CLI（给 AI 调），带自我进化（提案制），带 Git 同步。

**技术栈**：Rust workspace——`fsh-core` / `fsh-cli` 两 crate + Tauri 2 GUI（`src-tauri`，crate 名 `fsh-gui`）；crate 数量冻结，禁止新增；TS 只出现在 webview 前端。CLI 与 GUI 均单 exe。

**hub 布局**：portable——数据放安装目录下 `data\`，跟软件走；不写家目录、不写注册表，删目录即卸载。

---

## 1. 需求清单（验收以此为准）

1. 个人自用为主
2. GUI（人）+ CLI（AI）双入口，两边都能改，状态一致
3. 项目级固定 skill 集，手动或 AI 定（不要运行时动态揭露）
4. 自我进化（重点）
5. Git 同步 / 升级，GitHub 起步
6. 可视化

## 2. 架构

### 2.1 分层与 workspace（定稿）

```
fuyao-skills-hub/            # Cargo workspace
├─ crates/fsh-core/          # 纯逻辑：git、paths、hub、link、deploy、gc、backup、doctor
│  ├─ src/adapters/          # 规划中：声明式适配器（TOML 数据）——目录、格式方言、链接能力、降级策略
│  └─ src/git/               # ✅ git2（libgit2）封装——静态链接进 exe，不依赖用户装 git
├─ crates/fsh-cli/           # ⬜ clap → fsh 命令；全命令 --json，写操作 --dry-run
├─ src-tauri/                # 🟡 Tauri 2 薄桥（fsh-gui）：command 只调 fsh-core，不含业务逻辑
└─ src/                      # 🟡 React 19 + TS + Monaco —— 全项目唯一 TS 存在处
```

**模块数量冻结**：`crates/` 下只有 `fsh-core` 与 `fsh-cli`，禁止新增任何 crate；一切后续职责（适配器、索引等）一律作为 `fsh-core` 内部模块落地。

**铁律**：fsh-core 不知道任何具体 Agent 的名字；adapter 不知道 UI 的存在。业务逻辑 100% Rust。

### 2.2 hub 目录布局（portable，定稿）

```
E:\fuyao\                           # 安装目录，放哪都行（两条红线见 2.6）
├─ fsh.exe                          # CLI：单 exe，静态链接，零运行时依赖
├─ fuyao-skills-hub.exe             # GUI：Tauri 2 单 exe（WebView2 走系统组件）
└─ data\                            # hub 根 = 一个 git 仓库（真身是 .git）
   ├─ .git\                         # 真身：版本历史、tag、diff、审计、备份全在这
   ├─ .gitignore                    # 三行：store/*/*/（物化目录）、cache/、projects.toml
   ├─ hub.toml                      # tracked：user 身份、gc 配置、backup 提醒
   ├─ store\
   │  └─ <skill>\
   │     ├─ SKILL.md  references\   # tracked 工作副本 = 编辑面（可脏，无人链它）
   │     ├─ 1.0.0\                  # ignored 物化目录 = 部署面（链接靶子，可删/重建）
   │     └─ 1.1.0\                  # ignored；仅当有 lock 引用时存在
   ├─ meta\<skill>.toml             # tracked：来源、作者、tags、license
   ├─ proposals\                    # tracked：进化提案历史天然进 git
   ├─ projects.toml                 # ignored 登记簿：哪些项目在引用（路径+最后 apply 时间）
   └─ cache\                        # ignored：索引 + 日志；可随时重建
```

- exe 定位 hub 的规则只有一条：**自己所在目录下的 `data\`**。
- 版本实体是 git tag，命名空间 `<skill>/v<semver>`；`<skill>/stable` 充当稳定指针；仓库本地 `core.autocrlf=false`。
- 卸载 = 删安装目录，零残留；更新 = 覆盖 exe，`data\` 永不参与。

### 2.3 项目侧布局（已实现）

```
<project>\
├─ .fsh\
│  ├─ skills.toml                   # 人写：要哪些 skill、版本约束（精确 semver 或 stable）
│  ├─ skills.lock.toml              # 机器写：精确版本 + commit + 内容 hash + 链接方式 + 落点
│  └─ state.toml                    # 本机状态：实际链接、时间戳（不提交）
├─ .fsh\skills\<skill>              # 链接落点 → hub 物化目录
└─ .gitignore                       # 忽略链接落点目录
```

### 2.4 版本模型：git 为真身，物化为缓存（定稿 ✅）

版本的唯一实体是 git tag（`<skill>/v<semver>`）；`store\<skill>\<semver>\` 只是 tag 的按需物化（导出缓存），可随时删、按字节重建。

- **编辑面与部署面分离**：工作副本随便改、可以脏；项目链接只指向物化目录
- 入库 / bump = commit + tag + 物化，不复制目录
- 升级 / 回滚 = relink 到另一物化目录，秒级
- `fsh diff` = `git diff`；git log 是原始审计账本
- 漂移检测双向：项目侧（链接被改 / copy 内容被改 / 版本被删）+ hub 侧（工作副本被手改 / 物化与 tag 不符，blake3 内容哈希对比）

### 2.5 GC：及时、定向、无损（✅）

| 对象 | 策略 |
|---|---|
| 无 lock 引用的物化目录 | 清（grace_days 宽限内保留） |
| 孤儿目录（无对应 tag） | 清 |
| 内容与 tag 不符的脏目录 | 跳过并报警（可能是进化证据，绝不销毁） |
| git tag / 历史 | 永不清 |
| 登记簿死项目记录 | 清（grace_days 宽限） |

三层执行，零后台进程：① **顺手清**：apply 成功后当场查引用；② **`fsh gc [--dry-run]`**：全量，先列清单再执行；③ **doctor 只报不动手**。引用查找走登记簿 + 项目 lock（毫秒级），不扫盘；黑链接排查留给 `doctor --scan`。

### 2.6 链接引擎（Windows，✅）

三级降级，必须实现：目录符号链接 → junction → 带 hash 记账的拷贝（写 `.fsh-source.toml` 记来源，status 靠内容哈希报漂移）。已知坑：云盘路径破坏 reparse point（doctor 检测）；部分工具不跟进链接（adapter 声明「是否支持链接」，不支持强制 copy）；链接目录必须进 .gitignore。

### 2.7 portable 立场与三道保险

不往家目录写任何东西（产品立场，写进 README）。三道保险：① doctor 运行时安全检测（可写 / 非云盘 / 非 Program Files）✅；② exe 占用更新协议（旧 exe 改名 → 放新 → 启动删旧）⬜；③ 备份空窗兜底：`fsh backup <dest>` 打 zip ✅，doctor 对超 N 天未备份提示 ✅。

## 3. CLI 设计（⬜ 全部待接线，core 能力已备）

**设计原则（定稿时指导取舍）**：命令必须精简高效。首版允许冗余，随设计完善逐条收敛——每条命令要证明自己有不可替代的使用场景，证明不了就合并或删除。命令面逐条经用户拍板，不预设全集。

给 AI 用是第一优先级：**所有命令支持 `--json`，所有写操作支持 `--dry-run`**。

```bash
fsh init [--hub <url>]                      # ✅core  初始化 data\ 为 hub（或接远端）
fsh add <git-url|dir|zip> [--as name]       # ⬜ 入库，自动读 SKILL.md frontmatter —— M1 关键缺口
fsh list [--tag] [--json]                   # ⬜
fsh show <skill>[@ver]                      # ⬜
fsh version <skill> --bump patch|minor|major # ⬜ commit + tag + 物化（core 已备）
fsh link <skill>@<ver> --target claude-code,codex [--project .]  # 🟡 三级降级已备，adapter 映射未做
fsh unlink <skill> --project .              # 🟡 撤链已备
fsh remove <skill> [--purge]                 # ⬜ 删除两级：默认归档（git 仍管理、历史与 tag 全在、可恢复）；--purge 彻底删（git rm + 删全部 tag，git 不再管理）；命令形态 M1 grill 定
fsh restore <skill>                         # ⬜ 取消归档：从 git 历史取回工作副本，版本链原样恢复（回到旧版本不走这条——改清单版本号 + apply 即回滚）
fsh plan   [--project .] [--json]           # ✅core
fsh apply  [--project .]                    # ✅core（末尾顺手回收 + 登记簿 upsert）
fsh status [--project .] [--json]           # ✅core（非零退出码表示有漂移）
fsh gc     [--dry-run]                      # ✅core
fsh diff   <skill> <v1> <v2>                # ⬜ 即 git diff
fsh doctor [--scan]                         # 🟡 七项已备；--scan 扫黑链接推 M1
fsh backup <dest>                           # ✅core
fsh evolve <skill> [--since 7d]             # ⬜ 生成进化提案（M2）
fsh propose list|show|apply|reject <id>     # ⬜ 提案工作流（M2）
fsh sync [--push|--pull]                    # ⬜ 与远端 Git 同步（M3）
```

配套一个 `manage-skills` 伴生 skill：告诉 Agent 什么时候调哪个命令、`--json` 怎么读、禁止直接改 hub 文件。**这是「AI 自己管理」的落地点。**

### 适配器（M4，⬜）

每个工具一条 TOML 声明：安装目录、格式方言、链接能力、全局/项目级。第一批 3–5 个常用工具（DSH / Claude Code / Codex / Cursor）+ 自定义路径；每加一个 ≤ 半天。

## 4. GUI 设计（🟡 骨架在，页面全未实现）

五页，不多做：

1. **库（Library）**：卡片/表格，按 tag、来源筛；详情 + 内联编辑 SKILL.md（Monaco + 预览）
2. **版本（Versions）**：时间线、两版 diff、一键回滚、谁在用这个版本
3. **项目（Projects）**：lock 表、漂移状态、一键 plan → apply
4. **进化（Evolution）**：提案收件箱，左旧右新 + 证据，按钮：通过 / 拒绝 / 分叉 / 回滚
5. **适配器（Adapters）**：每个工具的路径、探测状态、链接能力、当前铺了哪些 skill

可视化只做四张图：使用与版本分布 / 项目 × skill 覆盖矩阵 / 引用图 / 进化 diff 评审。

## 5. 自我进化（M2，⬜）

闭环：`采集 → 归因 → 提案(diff) → 闸门 → 人审 → 新版本 + commit → 灰度 → 全量 / 回滚`

**证据来源**（只用高置信信号）：用户手改 skill 的 diff（最高置信）；用户显式纠正；同一失败 ≥2 次；任务成功但走了弯路；GUI 点赞/踩。不让 LLM 凭感觉猜。

**四道闸门**（缺一不可）：① 体积棘轮（净增长超阈值必须附证据）② 触发回归（description 还能不能被正确命中）③ 任务评测（before/after 对比）④ 人工否决（默认必须人点通过）。

**安全边界**：只提案不自动改；一次 apply = commit + 新 tag；先进项目级灰度再全局；提案必须带「删/并」候选——只允许加法的进化一定会膨胀。

## 6. 索引层（规划，M2+）

git 为真身，物化为缓存，SQLite 为索引（后两者可随时重建）。`skill` / `version` / `project` / `deployment` / `proposal` / `usage` 表，从第一天就要有的字段：`owner`、`version`、`source`、`applied commit`。
