# 模块结构约定：一个文件一个概念，上限 300 行

## 背景

`fsh-core` 的 13 个概念全部平铺在同一个源码目录下，最大的文件 758 行，改一个概念要先在几百行里重新定位它住在哪一段。同一目录里还并存三套约定：完整的目录模块、只有测试文件的半壳、只有 `mod.rs` 的空壳——「它是目录还是文件」推不出任何信息，人和 AI 都得先探索再动手。改一个概念的代价每次都付在「找到它」上。

## 备选

- 只按行数拆：行数达标了，但概念仍混在一个文件里，读的人还是要靠行号定位，放弃。
- 只按概念拆、不限行数：单个概念本身可以长到几百行，一次阅读装不下，放弃。
- 两条并用：概念是「拆」的判据，行数是「什么时候必须拆」的触发线，采用。

## 决策

一个文件只住一个概念。概念不止一个就用目录模块（`<名>/mod.rs` + 若干子文件），`mod.rs` 只放模块文档、错误类型、共用小件、子模块声明与重导出。任何源码文件不超过 **300 行**（测试文件同此标准），超了按概念再分。

## 理由

- 300 行是**唯一**的行数数字。它来自本项目的可读性取舍，不来自任何技能规范：`rust-patterns` / `rust-testing` 等技能不规定文件行数。
- 行数上限是「该拆」的触发线，**不是「必须合并」的义务**。两个按概念切开的文件合计不到 300 行时，保留切分是合法的。
- 测试跟着实现走：单文件模块的测试内联在文件末尾的 `#[cfg(test)] mod tests`；目录模块的测试住同目录的 `tests/` 子目录，按被测概念分文件，共享夹具集中在该子目录的 `mod.rs` 并标 `pub(super)`。不造「只有 `mod.rs` + `tests.rs`」的半壳——那等于用两个文件表达一件仍然只有一个概念的事。
- 概念名撞 Rust 关键字时，源码文件用下划线避让（`use_.rs` + `mod use_;`）；测试文件名要与被测概念同名、无法加下划线时，用 `#[path = "use.rs"] mod use_flow;`。
- 规则正文写在 `AGENTS.md` 的测试规范节，此处只记取舍，不重复条款。
