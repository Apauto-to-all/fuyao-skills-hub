# 写入口必须持锁令牌（capability token）

fsh-core 的全部写路径（技能管理、GC、hub 登记/备份）依赖进程级文件锁互斥，但「先取锁再动盘」只是各入口手写 `let _guard = write_lock(...)` 的约定——新增写入口时忘取锁不会编译失败，只会在线上变成数据竞争。决定：`lock` 模块提供 `WriteToken`（仅 `write_lock` 可构造），写路径的内部共享函数一律以 token 为参数，「忘锁」直接编译失败；锁内顺序不变量（先锁、再读登记簿、后写盘）写在 token 的类型文档上。

## Considered Options

- 维持约定 + 文档说明：已证明随调用点增长而脆弱，放弃。
- 全量两段化（先产动作清单再执行）：改动面远超收益，放弃。
